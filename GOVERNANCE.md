# Governance

## Project Roles

### Maintainers
Maintainers are responsible for the overall technical direction, reviewing pull requests, managing releases, and upholding project safety invariants.

Current maintainer:
- **Aman Awasthi** ([@amandeavor](https://github.com/amandeavor))

### Contributors
Anyone who submits issues, proposes improvements, writes documentation, or submits pull requests is a contributor.

## Becoming a Maintainer

Maintainership is based on sustained, high-quality technical contributions, careful review judgment, and reliability:
- Demonstrated understanding of CLI design, path safety, and Python best practices.
- Thoughtful triage of incoming issues and constructive code reviews.
- Adherence to conservative file-safety invariants and regression testing standards.

Maintainership is not granted automatically by a fixed commit count, but through consensus among active maintainers.

## Decision Process

- Minor improvements, bug fixes, and documentation updates follow normal pull request review.
- Architectural changes, new CLI flags, or changes to file-categorization heuristics should be proposed via a GitHub issue or discussion first.
